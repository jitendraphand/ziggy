# Simulation report v0.1.1 (MuJoCo 4.0.0)

Everything here is **simulation**. No hardware exists. Every number comes from `media/metrics.json`, regenerated by
`python tools/sim.py media`, and from the tests in `tests/test_sim.py`.

## Model and physics settings
| Item | Value | Note |
|---|---|---|
| Base | free joint at the pelvis (floating base, not pinned) | `test_physics_settings` |
| Gravity / timestep / integrator | −9.81 m/s², 2 ms, `implicitfast` | default contact solver (Newton, pyramidal cones) |
| Mass | 46.0 kg | budget in `params.MASS`, **not** a CAD rollup |
| Inertias | hand-estimated diagonal per link | should be replaced by CAD-derived values |
| Collision | soles collide with everything; limb, torso, head, palm and finger proxies collide **with the floor only** (self-collision off) | friction 0.9 / 0.01 / 0.001 (assumed, not a measured floor/TPU value) |
| Joint dynamics | armature 0.005–0.05 kg·m², damping 0.02–2 N·m·s/rad | rough guesses that keep the sim stable; real values come from actuator ID |

## F-008: falling robot passed through the floor (found from video review, fixed)
Video review reported that the falling robot "shatters into pieces".

**What the evidence showed.** Over the 300 N fall:
* Every child body stayed attached to its parent: max parent-child anchor residual 3e-16 m (machine precision). MuJoCo uses generalized coordinates, so the joint tree cannot separate.
* No state went non-finite.

The cause was the collision setup. v0.1.1 gave collision geometry only to the soles and hands, so once the robot tipped over, its pelvis, torso and head **sank through the floor plane**: pelvis z −0.23 m and head −0.58 m at the end of the run. The floor hid the buried parts, so the visible ones looked disconnected.

**The fix.** Every body proxy now collides with the floor. The robot does not collide with itself, so adjacent capsules can still overlap.

**After the fix** (300 N fall):
* minimum pelvis height 0.087 m (lying on the floor)
* max penetration 40 mm, a brief impact transient from MuJoCo's default soft contact (solref 0.02 s) under a 46 kg impact; 0.24 mm at rest
* finger-coupling equality violation at most 0.014 rad during the impact

`tests/test_sim.py::test_trajectory_integrity` guards all of these.

The standing and push numbers below did not change, because during standing only the soles touch the floor.
The push marker is a red arrow: bright while the force is applied (1.0–1.1 s), dim for 0.35 s afterwards, plus a "PUSH ACTIVE" caption. It is drawn on the video only; the force itself is applied to the pelvis.

## Actuation: what the servo model is and isn't
* MuJoCo `<position>` actuators with `gear = 1`, so actuator force equals joint torque in N·m.
  * Legs: kp = 400 N·m/rad, kv = 20.
  * Arms: kp = 120.
  * Wrists: kp = 20.
  * Fingers: kp = 2.
* Torque is clamped at the manufacturer **peak** rating (AK80-64 and RS04: 120 N·m; AK70-10: 24.8). Peak can only be held briefly, and continuous ratings are much lower (48 / 40 / 8.3 N·m).
* **Not modelled**: motor current and voltage limits, the torque-speed curve, thermal derating, gearbox backlash (0.18° for AK80-64), compliance, friction, CAN latency (control runs ideally at 500 Hz, every physics step), encoder quantisation and noise, IMU estimation (the controller reads the true CoM). Simulated balance is therefore an **optimistic upper bound**.
* **F-007, a bug fixed in this release**: with `compiler angle="degree"`, MuJoCo converts joint ranges but **not** actuator `ctrlrange`. v0.1.0 wrote its ctrlranges in degrees, so they were 57× too wide and did not clamp commands to joint limits. Ctrlranges are now in radians, and `test_actuator_units_gear_and_ctrlrange_radians` guards against a repeat.

## Controllers
* `pd`: every joint holds the zero posture. There is no balance feedback.
* `ankle`: `pd` plus an ankle strategy. The pitch and roll setpoints are 3.0·e_CoM + 0.5·v_CoM (rad per m, rad per m/s), clipped to ±0.6 / ±0.3 rad, using the **true** CoM and its velocity.
  * The gains were hand-tuned on the forward 0.1 s sweep, so backward, lateral and 0.2 s pushes count as held-out checks.
  * This is a linear standing controller. It is not whole-body control and not stepping.

## Balance metrics (definitions)
* **Support margin**: signed distance from the CoM ground projection to the edge of the convex hull of the soles **in contact** (contact normal force > 1 N). Positive means inside. A value of −1000 mm means no foot is in contact. The older `analysis.support_margin` assumes both soles are on the floor; it is used only for the static-standing check.
* **Fell**: pelvis drops more than 0.25 m, **or** trunk tilt exceeds 30°, **or** the CoM is outside the support area at the end of the run.
  * **F-006, a fix**: v0.1.0 used tilt and height only, so a slow topple at 200 N counted as "survived".
* **Recovered**: not fallen, CoM back within 10 mm of the pre-push position, and less than 3 mm peak-to-peak over the last 0.5 s. **Survived but not recovered** is reported separately.

## Results (deterministic; push applied at the pelvis from t = 1.0 s)
| Push | Controller | Max survived | Max recovered | First fall |
|---|---|---|---|---|
| +x (forward), 0.1 s | pd | 175 N (17.5 N·s) | **none** (underdamped, does not settle within 2.9 s) | 200 N |
| +x, 0.1 s | ankle | 250 N | 250 N (settles in 1.35 s, max CoM shift 85 mm, no saturation) | 275 N |
| +y (lateral), 0.1 s | pd / ankle | 200 / 200 N | 100 / 150 N | 250 / 250 N |
| −x (backward), 0.1 s | pd / ankle | 100 / 150 N | none / 150 N | 150 / 200 N |
| +x, 0.2 s (held out) | pd / ankle | 75 / 150 N | none / 150 N | 100 / 175 N |

Unperturbed standing with 1° random joint offsets (seeds 0–4) settled and recovered in all 5 runs (final CoM offset 0.5–4 mm).
At failure (ankle, 300 N) 4 actuators saturate at peak torque and the feet slip and lift. This is the failure shown in the media.

## IK (kinematic, no dynamics)
Damped least squares on MuJoCo site Jacobians, with joint-limit clamping and bounded random restarts.
* Reachable targets (from forward kinematics of random in-limit poses, 200 per arm): left 98.5% and right 100% within 1 mm, median 0.27 mm, joint limits respected 100%.
* Household targets (left hand, standing, waist optional):

| Target | Error | Result |
|---|---|---|
| Counter 0.90 m | 0.47 mm | reached |
| Door handle 1.00 m | 0.03 mm | reached |
| Light switch 1.20 m | 0.18 mm | reached |
| Shelf 1.40 m | 0.06 mm | reached |
| Table 0.75 m | 45 mm | **unreachable** |
| Floor 0.10 m | 690 mm | **unreachable** (needs squat / whole-body IK, not implemented) |

The IK media are kinematic interpolations to each solved pose. They are labelled as such and are not dynamic tracking.

## Not measured or not implemented
Robot self-collision (disabled), walking and stepping, whole-body or squat IK, dynamic arm tracking under load, grasp contact quality, actuator thermal
limits, model-to-hardware identification, state estimation, latency and noise robustness, slopes and uneven floors.
**Walking is not implemented. No result here shows walking.**

## Reproduce
```bash
MUJOCO_GL=egl python tools/sim.py media                      # all media + media/metrics.json (~45 s)
python tools/sim.py push --force 250 --controller ankle --seed 0 --duration 4 --out /tmp/push.mp4
python tools/sim.py sweep --controller pd --fmax 400 --step 25 --dir 0 1
python tools/view.py --controller ankle                       # interactive viewer (needs a display)
python -m pytest -q tests                                     # 94 tests
```
